# Phase 5.5 RAG quality validation report

## Scope

This run validates document parsing, metadata propagation, namespace separation, safe re-index behavior, and LangGraph evidence-handling branches with offline fakes. The repository contains a fictional demo corpus and no approved retailer corpus. The demo documents were not embedded or uploaded to Pinecone during this run.

A configuration-presence check found no OpenAI, Pinecone key/index, or DeepSeek settings configured (values were not displayed), so no real provider evaluation was run and no provider API calls were made.

## Re-index safety behavior

The app now uses a dedicated approved namespace and a separate demo namespace. IDs generated by this indexer use the eskb- prefix and contain a stable document ID plus a version digest over content and metadata. Synchronization lists only that prefix within the selected namespace. It upserts all new/changed chunks first, then deletes only exact stale IDs with the same prefix. A failed upsert leaves old vectors in place. The installed Pinecone SDK's list, upsert, and delete(ids=..., namespace=...) signatures were inspected locally.

If files remain in the selected directory, a regular indexing run removes managed vectors for files that were deleted. When the entire source directory is empty, deletion is intentionally opt-in:

    python -m app.rag.ingest --prune-empty

Review the selected directory and namespace before using that command. It deletes only eskb- IDs in the configured application namespace, not all index contents.

## Limitations and next validation

- The approved corpus is empty, so no real policy or retailer answer has been validated.
- Evidence evaluation is a single DeepSeek structured judgement when configured; the fake tests do not verify that judgment's semantic accuracy.
- Last-updated dates are included in Pinecone metadata and evaluator/generator context. A date alone is not treated as proof that a document is expired; document owners must withdraw or update superseded material.
- Pinecone changes are not transactional. Upsert-before-delete avoids losing the prior version on an upsert failure, but old and new versions may briefly coexist until stale-ID deletion succeeds or a later indexing run reconciles them.
- Old vectors from the earlier Phase 5.2 default namespace are not deleted automatically. The new app ignores that legacy namespace; cleanup should be a separately reviewed migration, not a broad delete.
- Run real retrieval and answer-quality evaluation only after approved documents are supplied and provider/index configuration is intentionally enabled. Record corpus revision, index namespace, model settings and test queries with that evaluation.
